Section 7 of your README lists K(4, 3) ∈ [18, 27] and K(3, 4) ∈ [21, 28] as the smallest open cases. We believe both upper bounds are the exact values:

- **K(3, 4) = 28.** Any Kakeya set of size ≤ 27 in F₄³ would contain a union of one line per direction in which some point lies on D ∈ {4, …, 8} of the chosen lines; up to PΓL(3,4) there are 39 (D, direction-set) subcases, each a CNF refuted by CaDiCaL with an LRAT proof checked by the formally verified checker cake_lpr. The upper bound is Dvir's set, which your repository also has.
- **K(4, 3) = 27.** A 26-point Kakeya set in F₃⁴ is reduced, by exact counting (moment identities over the 40 hyperplane directions, an additive-energy argument, and a SAT-certified table of how many directions a k-point subset of F₃³ can carry), to 9 slice-size types and 67 SAT cases with a small slice fixed up to AGL(3,3); all 67 are refuted with checked LRAT proofs. The 27-point witness is checked by an independent script. This settles the conjecture k₄ = 27 stated by Seva Lev in 2009 (comment 994 on the DHJ polymath thread, where k_r denotes the minimum Kakeya set in F₃^r). Note that Lev's k₅ = 53 question is about F₃⁵, not F₅³.
- **47 ≤ K(3, 5) ≤ 53.** The lower bound is an LP/Farkas-certificate chain: 82 reduction certificates and 8 root certificates over 330,860 degree-vector cases, each an integer multiplier vector re-applied exactly (Fractions) to rows regenerated by the research code (replayed in full in the repository, about 2 h); the hand lemmas behind the rows are documented and were audited by an independent session (none found false), but the row generators themselves are the original research code, so this bound rests on a larger trust base than the SAT results; the upper bound 53 is an explicit set (also the AlphaEvolve value ¼p³ + ⅞p² − ⅛ at p = 5). We do not claim 53 is optimal.
- **Planar Nikodym sets (every-point variant, as in Lund–Saraf–Wolf / Tao / the AlphaEvolve paper): Nik(2,7) = 36, Nik(2,8) = 48 and Nik(2,9) = 63.** Each is a short script-checked symmetry normalisation (flag for q = 7, 8; maximum-secant line for q = 9) followed by CNFs refuted with cake_lpr-checked LRAT proofs (Nik(2,9): 28 cases, 1128 UNSAT instances, about 50 CPU-hours of CaDiCaL), plus a SAT witness at the extremal size checked by an independent script.
